# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Commands

The package manager is pnpm (`pnpm-lock.yaml`). The repo is both the npm package `@vdeantoni/particle-network` and its demo site.

- **Dev server (demo):** `pnpm dev` (Vite, port 5173)
- **Library build:** `pnpm build` emits ESM `.js` and `.d.ts` files into `dist/` with `tsc -p tsconfig.build.json`, no bundler. `prepack` runs it, so `pnpm pack` and `pnpm publish` always ship a fresh build.
- **Demo build:** `pnpm build:demo` type-checks everything and builds the demo into `dist-demo/`; `vercel.json` points Vercel at that command and folder. `pnpm preview` serves it.
- **Type-check only:** `pnpm exec tsc`
- **Format:** `pnpm dlx prettier --write src demo` (Prettier isn't a devDependency; `.prettierrc` sets single quotes and trailing commas)
- **Package checks:** `pnpm dlx publint` and `pnpm dlx @arethetypeswrong/cli --pack . --profile esm-only` check that the exports and types resolve for consumers.

No test runner or linter is configured, so the builds and the package checks are the only automated checks. Publishing is manual: `pnpm publish` from a clean `main` after bumping `version`. `publishConfig` pins the public npm registry, because a machine-wide registry setting would otherwise receive the package.

## Architecture

This is a vanilla TypeScript canvas animation that renders a particle network: particles drift across a canvas and links are drawn between particles within `linkDistance`, with opacity based on proximity. The code says "link" for these lines; the panel's "Connections" and "Mouse" folders keep friendlier labels.

`src/` is the embeddable library, published with three entry points in `package.json` `exports`: `src/index.ts`, `src/panel.ts` (Tweakpane, so a page only loads it if it shows the panel) and `src/react.tsx`. Relative imports end in `.js` even though the files are `.ts`: `tsc` doesn't rewrite paths in `.d.ts` files, and consumers resolving the types need the extension of the emitted files. `demo/` is the full-screen demo site: `index.html` declares `<canvas id="canvas">` and the panel elements, then loads `demo/main.ts`, which creates the `ParticleNetwork` and the panel and owns the toggle button and the `h` shortcut. CSS in `demo/style.css` sizes the canvas to fill the viewport. The library never styles the canvas or the page; the embedding page does.

**Core modules:**

- **Settings** (`src/settings.ts`) holds `DEFAULT_SETTINGS`, the slider `RANGES`, and localStorage load and save. Loading clamps numbers to `RANGES` and drops wrong types and non-hex colors. Saving stores only values that differ from the network's configured settings, and never `paused`.
- **`ParticleNetwork`** (`src/particle-network.ts`) starts its `requestAnimationFrame` loop in the constructor and stops it in `destroy()`. It keeps two settings objects: `base`, the options' `settings` merged over `DEFAULT_SETTINGS`, and the public `settings`, which is `base` plus any values stored under `storageKey`. The panel's bindings mutate `settings` directly, and the loop reads it every frame, so changes apply live. `set()` changes both objects, so it also moves what `reset()` returns to; both notify `onChange` listeners, which is how the panel refreshes after a change made in code.
- Each frame, the loop fits the canvas, draws the background (or clears it when `background` is off), moves and wraps particles (unless paused or the user prefers reduced motion), then draws links and particles on top. An `IntersectionObserver` stops the loop while the canvas is off screen and restarts it with `last` reset, so the time away doesn't count as one long frame. Links use a grid of `linkDistance`-wide cells over the wrap area, so each particle is only compared with particles in its own and neighboring cells. `findNearbyPairs()` refills the grid only when lines are drawn (`lineWidth` above 0) or overlapping triangles need `adjacency`, so otherwise the cells hold a past frame's particles. Line opacity is `(1 - distance / linkDistance) ** falloff`, rounded to `ALPHA_LEVELS` steps so all lines of one level go in a single `Path2D` and one `stroke()`. Opacity is applied with `globalAlpha` rather than `rgba()` strings, which are costly to parse per particle. With triangles on, `fillTriangles()` fills triangles under the lines, shaded by their weakest or average edge level. The `mosaic` style takes the Delaunay triangulation (via `delaunator`) and keeps triangles whose edges are all links: they never overlap and number at most two per particle. The `overlapping` style fills every mutually linked triple, found from the per-particle `adjacency` recorded during the link pass (grid cells hold particle indices for this); its count grows with the square of each particle's neighbor count, so it gets slow when dense. Each triangle is filled on its own, because a single fill draws overlapping shapes once and batching made overlaps flicker. Per-triangle opacity lives in `fades`, keyed by the three particle indices, and eases toward its target over `triangleTransition` ms, including fading out after an edge breaks.
- **`Particle`** (`src/particle.ts`) holds position, a velocity inside the unit disk, and a `size` from 0 to 1. The network scales them by `maxSpeed` and the radius range at draw time, so those settings apply to existing particles.
- **Pointer interactions** live in the `ParticleNetwork`, which listens on its `pointerTarget`: the canvas by default, or `document.documentElement` for `'window'`, used when the canvas sits behind page content and never receives events itself. It stores the pointer in viewport coordinates and maps it onto the canvas every frame, so scrolling under a still mouse keeps it in place; positions outside the canvas count as no pointer. A primary-button press adds a particle while `spawnOnClick` is on, unless it lands on a link, button, form control or anything under `[data-particle-network-ignore]`, which the panel sets on its container. The new particle is `held`: each frame pins it to the pointer until `pointerup`, listened for on `window` so a release anywhere ends the drag. A `pointercancel` removes it again, because that's the browser taking a touch over to scroll. While a particle is held, `selectstart` and `dragstart` on the document are cancelled, so the drag doesn't also select text or drag an image; the `pointerdown` itself is left alone, because pages rely on it for focus and for dismissing popovers. A spawned particle gets a random drift and size like the others; it adds to the population until `randomize()` or the next time `fit()` acts, which trims the list back to the density's count. Forces never change a particle's own drift: they add to its `pushX`/`pushY`, which decays by `PUSH_DECAY` per reference frame so pushed particles settle back. The `pointerForce` modes (attract, repel, vortex) apply within `forceRadius`. Pointer links add lines from the pointer to particles within `linkDistance`. Pointer triangles join the pointer to pairs of particles linked to it and to each other (all pairs when overlapping, angular neighbors when mosaic). They share the triangle fades with `POINTER_INDEX` as their third index and vanish when the pointer leaves. The flashlight multiplies line and triangle opacity near the pointer.
- **Panel** (`src/panel.ts`) builds the Tweakpane controls in a container the caller provides and returns `destroy()`. It calls `network.save()` on each finished change, skipping the FPS monitor, which emits `change` on every poll.
- **React** (`src/react.tsx`, marked `'use client'` for Next's server components) wraps both. `<ParticleNetworkCanvas>` creates the network in an effect, destroys it on unmount, and hands it out through `ref`. Its `settings` prop is compared with the last one applied, so only changed keys reach `set()`: an inline object would otherwise undo panel edits on every render. A key dropped from the prop goes back to its default. `<ParticleNetworkPanel>` imports `./panel.js` dynamically, which bundlers split into its own chunk. `<ParticleNetworkSettings>` wraps the panel in a toggle button with a keyboard `shortcut` (default `h`, skipped while focus is in a text field) and Escape to close. Its button carries inline default styles unless `buttonClassName` is given, because the library ships no CSS for a class to override.

Behavior that spans these files:

- `REFERENCE_FPS` in `settings.ts` only sets the unit of time, not a frame cap. The loop runs at the display's rAF rate, and `delta` is elapsed time in units of `1000 / REFERENCE_FPS` ms (`FRAME_MS`), so `maxSpeed` is pixels per reference frame.
- The wrap area is the canvas plus a `linkDistance` margin on every side, so lines fade out before a particle jumps to the other side. Wrapping is modular, so a huge `delta` after the tab was hidden doesn't pile particles onto the boundary.
- Particle count and spawn positions cover the whole wrap area, so the visible density matches `density`.
- `fit()` runs every frame and acts when the canvas's CSS size, `devicePixelRatio`, `linkDistance` or `density` changes. On a size change it sizes the backing store in device pixels and scales the context, so all simulation and drawing code works in CSS pixels. It then stretches existing particles to the new wrap area, rebuilds the grid, and adds or removes particles to keep the density.

## Tech Stack

- TypeScript (strict mode, ES2023 target)
- Vite 8 (dev server and demo build, uses Rolldown), no `vite.config`, so Vite defaults apply
- No framework in the core: direct Canvas 2D API. React is an optional peer dependency used only by `src/react.tsx`, and only `@types/react` is installed, because nothing in the repo renders React.
- Runtime dependencies: Tweakpane 4 for the control panel, and `delaunator` for the mosaic triangles. Tweakpane's type declarations import `@tweakpane/core`, so that devDependency is required for `tsc` even though nothing imports it directly.
